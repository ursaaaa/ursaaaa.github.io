计算机背景的人进银行，第一道坎往往不是技术栈，是黑话。《银行业务入门》和《支付与清算入门》里就出现过这个问题：解释一个术语，顺手又带出两三个新名词，名词递归没有出口。这篇是系列配套的**词典**——不追求从头读到尾，追求查得到。

收词约定：只收银行科技需求文档里的高频词；每条先给一句话解释，再给一个程序员类比。类比服务直觉，不追求会计学意义上的严谨。

## 账务语言

最硬核的一组，先啃下来，后面所有组都用到。

**复式记账**：任何一笔资金变动都在两个及以上科目同时登记，一边记借、一边记贷，金额相等。程序员的锚点：**每笔事务强制双写，且带平衡校验**——账不平，事务直接失败。几百年会计准则的本质是一个数据一致性协议。

**借 / 贷**：只是记账方向符号（左 / 右），跟「借钱」「信贷」毫无关系——这是计算机人误读率最高的两个词。哪边记增加，取决于账户性质：

| 账户性质 | 例子 | 增加记 | 减少记 |
| --- | --- | --- | --- |
| 资产、费用 | 银行放出的贷款、付的利息 | 借 | 贷 |
| 负债、收入 | 储户存款、利息收入 | 贷 | 借 |

例子：储户存 1000 块，银行视角——现金是资产，增加记借；欠储户的存款是负债，增加记贷。两边各 1000，这就是「有借必有贷，借贷必相等」。

**科目**：账户的分类编码体系，会计核算的最小归类单位。像一张全局枚举表：每个账户必须挂在某个科目下，报表按科目出。

**流水**：逐笔交易日志。append-only，只插入不修改，记错了用反向交易**冲正**（再插一条方向相反的），这是审计的硬要求——别想着 update。

**总账与分户账**：总账是按科目汇总的余额表（聚合视图），分户账是按单个账户记录的余额明细（物化状态）。和流水的关系一层层物化：

```mermaid
flowchart LR
    T[一笔交易] -- 逐笔写入 --> F[流水]
    F -- 累加到账户 --> H[分户账]
    H -- 按科目汇入 --> G[总账]
```

**挂账**：暂时说不清去向或归属的钱，先记进一个「待处理」性质的**过渡科目**，查清楚再转走。像重试队列或死信队列：不是终态，必须有人跟进消化。

**日终跑批**：联机交易平峰后跑的批量作业——计息、计提费用、生成对账文件、更新总账。像 nightly cron job，但窗口和依赖管理严格得多，跑批失败是要凌晨拉人起来的事故。

**日切**：系统「营业日」的切换时点。银行的一天不是 0 点到 24 点：小额系统每天 16:00 日切，大额 17:30。跨系统对数据时，别假设大家在同一个「一天」里。

**对账**：把己方流水和对手方的清算文件逐笔核对。差账两个方向：**长款**（多收了，比如客户重试但首笔其实成功）、**短款**（少收了）。

**计提**：按规则预先把一笔金额计入费用或准备金科目——钱没有真实划走，纯账面动作（accrue）。按月计提利息、为坏账计提**拨备**，都是这个词。

**碰账**：动账、接触账务的口语说法。「渠道不碰账」意思是渠道只做交互、不直接记账，账必须落核心。

## 信贷语言

银行利润发动机的词汇表。

**授信**：给客户核定的信用上限和有效期，先审批、后用钱。像一张 pre-approved 的 credit limit，批了不等于用满。

**额度**：授信的可用余额，放一笔扣一笔，还款恢复。信贷系统里的高频字段，也是超放风险的控制点。

**借据**：一笔放款的合同实例——贷款表里带生命周期状态机的一行（放款、还款中、结清、不良）。需求文档说「查借据」，就是查这个实例的状态和余额。

**放款**：按借据把钱打给客户，审批结果正式变成一笔生息资产。

**还款计划**：本金和利息的分期时间表。等额本息、等额本金、先息后本，是三种常见的摊还方式，计划表是信贷核心表之一。

**逾期**：过了约定还款日没收到钱。一旦逾期触发罚息、催收，状态字段连带变化。

**五级分类**：贷款健康度枚举——正常、关注、次级、可疑、损失。**不良**是后三类的统称，监管最看重的口径。

**拨备**：为预计坏账提前计提的准备金。信贷的真实利润 = 利息收入 − 资金成本 − 拨备 − 运营成本，读信贷需求时脑子里要挂着这个公式。

## 资金与监管语言

**利差**：存款利率与贷款利率之间的差额（spread），银行最主要的利润来源。行业也常说**净息差**（NIM，Net Interest Margin）：净利息收入除以生息资产，衡量银行赚钱能力的核心指标。《银行业务入门》开篇讲的那门生意就是它。

**存款准备金**：吸收存款后按比例必须存在央行的钱，不能全部拿去放贷。比例由央行调整，本身就是货币政策工具。

**资本充足率**：自有资本 ÷ 风险加权资产，监管红线。每笔贷款按风险权重吃资本，资本稀缺，所以银行偏爱不占资本的中间业务。

**表内 / 表外**：进不进资产负债表。表内业务（存款、贷款）占资本；表外业务（担保、代销、托管）不占或低占资本，但可能有或有风险。

**或有负债**：现在还不是债、未来是否变成债取决于某件事是否发生的义务（contingent liability）——典型如担保承诺，被索赔了才真正负债。「或有风险」「或有事项」同源。

**净值化**：理财产品像基金一样按净值申购赎回、涨跌自负，不再承诺保本保收益。2018 年资管新规后的监管方向，终结了「保本理财 + 表外资金池」的老模式——《银行业务入门》埋的伏笔，系列写到理财篇时展开。

**备付金**：支付宝微信这类支付机构存在银行的客户资金。「断直连」后集中缴存、不得挪用，是第三方支付监管的关键词。

**头寸**：某一时点资金头寸 = 可用资金的富余或缺口，position。「头寸紧」就是钱不够了，要去市场上拆借。

**同业**：银行之间的业务统称——同业拆借、同业存款、同业存单。银行自己也互相借钱，是货币市场最大的参与者。

## 支付清算缩写

支付文档是缩写重灾区，一张表备查（详见《支付与清算入门》）：

| 缩写 | 英文全称 | 中文 |
| --- | --- | --- |
| CNAPS | China National Advanced Payment System | 中国现代化支付系统，人行大小额与 IBPS 的总称 |
| HVPS | High-Value Payment System | 大额支付系统 |
| BEPS | Bulk Electronic Payment System | 小额批量支付系统 |
| IBPS | Internet Banking Payment System | 网上支付跨行清算系统，俗称超级网银 |
| RTGS | Real-Time Gross Settlement | 实时全额结算，大额系统的结算模式 |
| CUPS | China UnionPay Switch | 银联的跨行交易清算系统 |
| NUCC | NetsUnion Clearing Corporation | 网联清算 |
| CIPS | Cross-border Interbank Payment System | 人民币跨境支付系统 |

## 机构与角色

**央行 / 商业银行 / 政策性银行**：央行（人民银行）是发钞、监管、运营支付清算网络的机构，不对个人办业务；商业银行做存贷汇的生意；政策性银行（如国开行）承担国家指定的融资任务。

**总行 / 分行 / 支行**：总部、省级机构、网点，一棵树。系统权限、核算层级、需求话语权都沿这棵树分布——「分行定制需求」就是树中间层的声音。

**柜面 / 柜员**：网点柜台这个渠道，和坐在柜台后的操作员。柜面系统是银行最老的在线交易系统之一，界面风格老派，但账务逻辑最完整。

**客户经理**：对外营销和服务角色，拉存款、放贷款、卖理财都是他们。系统里的「营销」需求，甲方通常就是这个角色。

## 系统黑话

**核心 / 核心系统**：银行的总账本，存款、贷款、会计核算都在其中。所有业务系统兜兜转转都落回核心记账。

**渠道**：客户触点层——手机银行、网上银行、柜面、ATM。原则：渠道不碰账，账务回落核心。

**前置 / 接口平台**：银行与外部机构（人行大小额、IBPS、网联、银联）之间的报文网关，管收发、加签验签、重发。

**联机 / 批量**：OLTP 与 batch。白天联机交易，夜里批量跑账，银行系统两大形态，架构和团队都常按此切分。

**投产**：deploy 上生产。银行变更窗口严格、审批链长，大量变更集中在深夜窗口——「今晚投产」是银行科技人的共同记忆。
